================================================================================
สรุปโครงสร้างฐานข้อมูล Firestore ของ SchoolLeaveApp
วันที่อัปเดต: 16 กรกฎาคม 2569
================================================================================

[ ภาพรวม ]
- ฐานข้อมูลหลัก: Firebase Firestore (Database ID: `school`)
- คอลเลกชันหลักที่พบในโค้ด: `Teachers`, `Leaves`, `UserRoles`, `Settings`, `FiscalRounds`
- คอลเลกชันกำหนดสิทธิ์/เมนู: `Permissions`, `MobilePermissions`
- คอลเลกชันข้อมูลแม่แบบ: `AdminRoles`, `Roles`, `Positions`, `Academics`, `LeaveTypes`, `Departments`
- คอลเลกชันวันหยุด: `SpecialHolidays`
- คอลเลกชันบันทึกการเข้าใช้งาน: `LoginLogs`

--------------------------------------------------------------------------------
[ 1) Teachers ]
--------------------------------------------------------------------------------
ใช้เก็บข้อมูลครูและบุคลากร

ฟิลด์ที่พบจากโค้ด:
- `username`
- `password`
- `fullName`
- `email`
- `role`
- `permission`
- `position`
- `department`
- `firebase_uid`
- `originalPassword`
- `forgotPasswordStatus`
- `tempResetCode`
- `resetAllowedUntil`
- `tempPassword`
- `lastSyncAt`
- `passwordMigratedAt`
- `created_at`
- `updated_at`

หมายเหตุ:
- ระบบใช้ `role` และ `permission` ในการอ่าน/เขียนสิทธิ์
- `fullName` ใช้เป็นชื่อแสดงผลหลัก

--------------------------------------------------------------------------------
[ 2) Leaves ]
--------------------------------------------------------------------------------
ใช้เก็บใบลา

ฟิลด์ที่พบจากโค้ด:
- `uid`
- `requestId`
- `timestamp`
- `status`
- `lastUpdatedAt`
- `fullName`
- `userId`
- `role`
- `position`
- `department`
- `leaveDate`
- `leaveType`
- `reason`
- `startDate`
- `endDate`
- `days`
- `totalDays`
- `year`
- `receiveNumber`

หมายเหตุ:
- ตอนส่งใบลา ระบบจะใส่ `uid`, `requestId`, `timestamp`, `status`
- รายงานสรุปการลาใช้ `fullName`, `startDate`, `endDate`, `leaveType`, `status`

--------------------------------------------------------------------------------
[ 3) UserRoles ]
--------------------------------------------------------------------------------
ใช้ผูก UID กับสิทธิ์ของผู้ใช้

ฟิลด์ที่พบจากโค้ด:
- `role`
- `permission`
- `fullName`
- `teacherDocId`
- `lastSyncAt`

หมายเหตุ:
- document id ใช้เป็น `uid`

--------------------------------------------------------------------------------
[ 4) FiscalRounds ]
--------------------------------------------------------------------------------
ใช้เก็บรอบปีงบประมาณ

ฟิลด์ที่พบจากโค้ด:
- `year`
- `round`
- `startDate`
- `endDate`
- `isActive`
- `createdAt`

หมายเหตุ:
- ระบบรายงานสรุปการลาใช้ข้อมูลรอบงบประมาณเพื่อกรองช่วงวันที่

--------------------------------------------------------------------------------
[ 5) Settings ]
--------------------------------------------------------------------------------
ใช้เก็บค่าตั้งค่าของระบบหลายแบบ โดยแต่ละ document มีโครงสร้างต่างกัน

document: `app_config`
- `secretKey`
- `appsScriptUrl`
- `driveProfileFolderId`
- `driveLeaveFolderId`

document: `line_messaging`
- `groupId`
- `webhookUrl`
- `template`
- `updatedAt`

document: `dropdowns`
- `positions`
- `ranks`
- `departments`
- `roles`
- `adminPositions`
- `leaveTypes`

หมายเหตุ:
- `dropdowns` เก็บเป็น array ตามชื่อ field

--------------------------------------------------------------------------------
[ 6) Permissions ]
--------------------------------------------------------------------------------
ใช้กำหนดสิทธิ์การมองเห็นเมนูบนหน้า PC

โครงสร้างเอกสาร:
- document id = ชื่อ role เช่น `ผู้ดูแลระบบ`, `ผู้บริหาร`, `ครู`

ฟิลด์ที่พบจากโค้ด:
- key แบบเลข `0` ถึง `8` เป็น boolean
- key แบบชื่อเมนูเดิมภาษาไทยก็ยังรองรับอยู่
- `updatedAt`

หมายเหตุ:
- เป็นสิทธิ์ระดับเมนู ไม่ใช่สิทธิ์ข้อมูลในรายงาน

--------------------------------------------------------------------------------
[ 7) MobilePermissions ]
--------------------------------------------------------------------------------
ใช้กำหนดสิทธิ์การมองเห็นเมนูบนมือถือ

โครงสร้างคล้าย `Permissions`
- document id = ชื่อ role
- key แบบเลข `0` ถึง `8` เป็น boolean
- `updatedAt`

--------------------------------------------------------------------------------
[ 8) AdminRoles ]
--------------------------------------------------------------------------------
ใช้เป็น master data ของตำแหน่งงานบริหาร

โครงสร้าง:
- โดยทั่วไปเป็น document เดี่ยว ๆ ที่เก็บค่าข้อความ 1 ค่า

หมายเหตุ:
- โค้ดอ่านค่าแบบ dynamic จาก document

--------------------------------------------------------------------------------
[ 9) Roles ]
--------------------------------------------------------------------------------
ใช้เป็น master data ของสิทธิ์/บทบาท

โครงสร้าง:
- ส่วนใหญ่เป็น document เดี่ยว ๆ ที่เก็บค่าข้อความ 1 ค่า

--------------------------------------------------------------------------------
[ 10) Positions ]
--------------------------------------------------------------------------------

โครงสร้าง:
- document เดี่ยวที่เก็บค่าข้อความ 1 ค่า

[ 11) Academics ]

--------------------------------------------------------------------------------
[ สรุปสั้น ]
--------------------------------------------------------------------------------
- ข้อมูลตัวบุคคลหลักอยู่ที่ `Teachers`
- สิทธิ์ผูกผู้ใช้จริงอยู่ที่ `UserRoles`
- ใบลาอยู่ที่ `Leaves`
- รอบงบประมาณอยู่ที่ `FiscalRounds`
- ค่าตั้งค่าระบบอยู่ที่ `Settings`
- สิทธิ์เมนูอยู่ที่ `Permissions` และ `MobilePermissions`
- master data อยู่ที่ `AdminRoles`, `Roles`, `Positions`, `Academics`, `LeaveTypes`, `Departments`
- วันหยุดอยู่ที่ `SpecialHolidays`
- ประวัติเข้าใช้งานอยู่ที่ `LoginLogs`
